# PLAN-03 — ResetPasswordScreen + ResetSentScreen

## Scope

Two screens covering the reset flow.

**New files:**
- `src/components/auth/ResetPasswordScreen.tsx`
- `src/components/auth/ResetPasswordScreen.test.tsx`
- `src/components/auth/ResetSentScreen.tsx`
- `src/components/auth/ResetSentScreen.test.tsx`

## ResetPasswordScreen

### Props
```ts
interface Props {
  onBack: () => void;
  onSent: () => void;
}
```

### Behavior
- Renders `BackButton` (calls `onBack`), `<h1>{t.resetTitle}</h1>`, `<p>{t.resetHint}</p>`, `Field` for email, error slot, primary submit.
- Submit: `disabled={busy}`, label `busy ? t.resetSubmitBusy : t.resetSubmit`, `disabled:opacity-60`.
- Empty email → inline `t.resetEmptyError`, do not call API.
- Successful `resetPassword(email)` → `onSent()`.
- Rejection → inline error from `err.message`.
- Error clears on next email change.

### Tests (mock `../../firebase/auth`)
- Renders heading, hint, field, submit, back button.
- Empty submit → `t.resetEmptyError` shown, resetPassword not called.
- Click back → `onBack()`.
- Successful submit → resetPassword called with email; `onSent()` called.
- Busy state: while pending, button disabled and shows `t.resetSubmitBusy`.
- Rejection → shows error message.

## ResetSentScreen

### Props
```ts
interface Props {
  onBackToLogin: () => void;
}
```

### Behavior
- Renders `<h1>{t.resetSentTitle}</h1>`, `<p>{t.resetSentBody}</p>`.
- Secondary outlined button `t.resetBack`: `w-full border border-hairline text-accent rounded-field py-3`.
- Click → `onBackToLogin()`.

### Tests
- Renders title and body strings.
- Renders button; click → `onBackToLogin()`.

## Constraints

- Both screens wrap content in `AuthShell`.
- Tailwind only; no inline styles.
- Strict TS.
