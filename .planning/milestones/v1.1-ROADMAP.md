# Milestone v1.1: Mobile Redesign

**Status:** ✅ SHIPPED 2026-05-04
**Phases:** 3-9 (7 phases)
**Total Plans:** 30 (5+7+3+4+5+5+4)

## Overview

Mobile-first dark-theme redesign of Todo Witek with locked OKLCH token system, Tailwind v4 styling, drawer-based category navigation, per-row overflow menu with inline edit and 2-step delete, bottom-sheet reminders, settings sheet with 5-color accent picker, and a redesigned three-screen auth flow. All copy in Polish; existing functional features (categories, reminders, push, offline-first Firestore, local mode) preserved.

Delivered against the locked hifi spec at `redesign/design_handoff_todo_witek/README.md`.

## Milestone Summary

**Decimal Phases:** none.

**Key Decisions:**
- Use Tailwind v4 (CSS-first `@theme` directive) — single source of truth for OKLCH tokens, auto-generated utilities (bg-bg, text-textDim, etc.); no `tailwind.config.js`.
- Accent palette as 5 keys with Polish labels; runtime swap via `document.documentElement.style.setProperty('--color-accent', ...)`; Firestore persistence at `users/{uid}/preferences/accent`.
- All ephemeral UI state (drawer open, menu anchor, editing id, reminders sheet, settings sheet) lives INSIDE MainList — no global store, no router. Established Phase 5; followed Phases 6/7/8.
- Animation strategy: CSS transitions only — no framer-motion or react-spring dependency. View-transitions API for FLIP-style moves where supported, with `motion-reduce` fallbacks throughout.
- Drag-to-reorder preserved with dnd-kit but switched to long-press activation (PointerSensor delay 250ms / tolerance 5px). No visible handle.
- Sheet primitive (Phase 7) reused by Phase 8 SettingsSheet — single drag-down/scrim/Esc model.
- Replaced (not deprecated) all legacy components per CLAUDE.md "no backwards-compat hacks": old CategoryTabs/TodoForm/TodoList/TodoItem/SortableTodoItem/ReminderEditor/Login/StorageModeToggle/PushToggle/InstallButton all deleted with their tests.
- Auth state machine local to AuthRouter — no router dependency for one screen flow.

**Issues Resolved:**
- Recovered from a mid-session VM crash that corrupted 6 git objects without losing any work — the dangling-commit chain was reachable via `git fsck --lost-found` and main was restored by pointing the ref at the recovered tip (39ee699).
- Polish plural correctness for relative-time labels delegated to `Intl.RelativeTimeFormat('pl')` instead of hand-rolled rules.

**Issues Deferred:**
- 30 human_needed visual confirmations across the 7 phases (animations, swipe gestures, native datetime-local picker, real Firebase login flow). All require browser/device testing pre-deploy. None are code blockers.
- PopoverMenu (Phase 6) scroll-out-of-viewport auto-close: specified in CONTEXT but not wired. Low impact — most scrolls trigger click-outside which already closes the menu.
- PopoverMenu bottom-edge viewport handling: only right-edge clamp wired in Phase 6.
- Push-from-right transitions between auth screens (Phase 9): currently instant swap.

**Technical Debt Incurred:**
- Phase 6 `confirming` state lives in MainList (keyed by todo id) rather than per-row TodoRow as originally planned in CONTEXT. Rationale documented in 06-SUMMARY: the popover renders from MainList so items[] reconstruction needs the state co-located with the menu. Functionally still per-row.
- `firestore.rules` for the new `users/{userId}/preferences/{document}` path has unit-test coverage at the wrapper layer but no emulator-rules harness exists in this repo. Manual deploy verification required when next deploying rules.
