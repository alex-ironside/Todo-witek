# Plan 04 — MainList integration: menu state, edit, and 2-step delete

## Goal
Wire `MainList` to:
- own `menuForId`, `menuAnchorRect`, `editingId`, and `confirmingDeleteId`.
- render `<PopoverMenu>` with three items: Edytuj / Przypomnij / Usuń.
- the Usuń item flips its label to `Na pewno?` (in `text-danger`) when
  `confirmingDeleteId === menuForId`. First Usuń tap arms confirm + 2s
  timer; second tap deletes and closes the menu.
- Edytuj sets `editingId` and closes the menu.
- Save calls `repo.update(id, { title })` and clears `editingId`.
- Cancel clears `editingId` only.
- Przypomnij calls `onOpenReminders?.(id)` (default no-op until Phase 7).

### Green
Inside MainList:
```tsx
const [menuForId, setMenuForId] = useState<string | null>(null);
const [menuAnchorRect, setMenuAnchorRect] = useState<DOMRect | null>(null);
const [editingId, setEditingId] = useState<string | null>(null);
const [confirmingDeleteId, setConfirmingDeleteId] = useState<string | null>(null);
const confirmTimerRef = useRef<number | null>(null);

useEffect(() => () => {
  if (confirmTimerRef.current) window.clearTimeout(confirmTimerRef.current);
}, []);

const closeMenu = () => {
  setMenuForId(null);
  setMenuAnchorRect(null);
  setConfirmingDeleteId(null);
  if (confirmTimerRef.current) window.clearTimeout(confirmTimerRef.current);
};

const openOverflow = (id: string, rect: DOMRect) => {
  setMenuForId(id);
  setMenuAnchorRect(rect);
  setConfirmingDeleteId(null);
};

const handleEdit = () => {
  if (menuForId) setEditingId(menuForId);
  closeMenu();
};

const handleDelete = () => {
  if (!menuForId) return;
  if (confirmingDeleteId === menuForId) {
    const id = menuForId;
    closeMenu();
    void repo.delete(id);
  } else {
    setConfirmingDeleteId(menuForId);
    if (confirmTimerRef.current) window.clearTimeout(confirmTimerRef.current);
    confirmTimerRef.current = window.setTimeout(() => {
      setConfirmingDeleteId(null);
      confirmTimerRef.current = null;
    }, 2000);
  }
};

const handleReminders = () => {
  if (menuForId) onOpenReminders(menuForId);
  closeMenu();
};
```

Items array passed to PopoverMenu:
```ts
const items = menuForId ? [
  { label: t.edit, onClick: handleEdit },
  { label: t.remind, onClick: handleReminders },
  {
    label: confirmingDeleteId === menuForId ? t.deleteConfirm : t.delete,
    danger: true,
    onClick: handleDelete,
  },
] : [];
```

But the menu's own item-click handler currently auto-closes the menu after
firing. For the delete first-tap we want the menu to stay open. Solution:
PopoverMenu's auto-close behavior is removed for items that return `false`
or we simplify by NOT auto-closing in PopoverMenu — the parent decides
(handleEdit/handleReminders call closeMenu themselves; handleDelete only
calls closeMenu on the confirm tap). Update Plan 01's PopoverMenu to NOT
auto-close on item click; the item's onClick is fully responsible. Update
PopoverMenu test accordingly.

i18n additions: `remind: 'Przypomnij'`, `deleteConfirm: 'Na pewno?'`. The
existing `delete: 'Usuń'`, `edit: 'Edytuj'`, `save: 'Zapisz'` already exist.
(Existing `deleteConfirm: 'Potwierdź usunięcie'` will be REPLACED with
`'Na pewno?'` per spec.)

Save handler: `void repo.update(id, { title }); setEditingId(null);`
Cancel: `setEditingId(null);`

Pass to OpenTodoList/DoneSection an `onOpenOverflow` (now `(id, rect) => void`)
plus `editingId`, `onSaveEdit`, `onCancelEdit`. Those forward the props down
to each TodoRow. TodoRow gets `isEditing={editingId === todo.id}`.
