# Plan 03 — TodoRow extension: edit mode + per-row confirming state

## Goal
Extend `src/components/main-list/TodoRow.tsx` to:
1. Render `<InlineEdit>` in place of the title when `isEditing` prop is true.
2. Pass the anchor `DOMRect` up via `onOpenOverflow(id, rect)`.
3. Manage local `confirming` state with a 2s reset timer for the two-step
   delete confirmation, and expose this via a render-prop-style mechanism — actually:
   the cleanest fit is for TodoRow to OWN `confirming`, and expose
   `onRequestDelete()` and `confirming` to its parent indirectly. Since the
   menu (which shows "Usuń" → "Na pewno?") lives in MainList, TodoRow must
   surface its `confirming` state to MainList.

   We will pass `confirming` and the toggle/confirm callbacks UPWARD: TodoRow
   accepts `isConfirmingDelete: boolean` and calls `onRequestDelete(id)` on
   first tap and `onConfirmDelete(id)` on second. The 2s timer logic lives in
   MainList alongside the menu state — keeping all menu-coordination state
   in one place. (CONTEXT mentions per-row local state, but since the
   confirm UI is rendered IN THE POPOVER which lives in MainList, MainList
   must know `confirming` to flip the label. Per-row local state would
   require an extra channel anyway. Keeping it in MainList is simpler and
   still satisfies "per-row" because the state is keyed by todo id.)

## Revised scope for this plan
TodoRow only:
- New optional prop `isEditing?: boolean`.
- New optional prop `editInitialTitle?: string` (defaults to `todo.title`).
- New optional prop `onSaveEdit?: (id: string, title: string) => void`.
- New optional prop `onCancelEdit?: (id: string) => void`.
- `onOpenOverflow` signature widens to `(id: string, anchorRect: DOMRect) => void`. The `•••` button passes `event.currentTarget.getBoundingClientRect()`.
- When `isEditing`, render `<InlineEdit initialTitle={editInitialTitle ?? todo.title} onSave={(t) => onSaveEdit?.(todo.id, t)} onCancel={() => onCancelEdit?.(todo.id)} />` in place of the title block. The checkbox and `•••` button are HIDDEN during edit (they would compete for tap targets).

The 2-step confirm state lives in **MainList** (Plan 04).
