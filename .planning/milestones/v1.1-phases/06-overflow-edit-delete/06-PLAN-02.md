# Plan 02 — InlineEdit (input + Zapisz)

## Goal
Create `src/components/main-list/InlineEdit.tsx` — replaces the row content
during edit mode with a single-line text input and a `Zapisz` button.
Keyboard-friendly: Enter saves, Esc cancels, blur cancels (mobile-first).

## TDD

### Red — `src/components/main-list/InlineEdit.test.tsx`
- renders the input with the supplied `initialTitle` as its value.
- on mount the input is focused AND its text is selected (`selectionStart === 0 && selectionEnd === length`).
- pressing Enter calls `onSave` with the trimmed value.
- pressing Enter with whitespace-only value calls neither `onSave` nor `onCancel`; the input shows a `ring-danger` class (or similar danger ring class).
- pressing Enter with a value identical (after trim) to `initialTitle` calls `onCancel` (no-op write) and NOT `onSave`.
- clicking the `Zapisz` button submits (same path as Enter). The button uses `onMouseDown` with `preventDefault` so blur-cancel does not race the click.
- pressing Esc calls `onCancel`.
- losing focus (`blur`) calls `onCancel`.
- typing then submitting passes the trimmed new title to `onSave`.

Run red.

### Green
Component shape:
```tsx
interface InlineEditProps {
  initialTitle: string;
  onSave: (title: string) => void;
  onCancel: () => void;
}
```
Internal state: `value`, `error`. Refs: `inputRef`. `useEffect` on mount focuses
and `select()`s. Enter handler / Zapisz click both call `submit()`:
```ts
const next = value.trim();
if (!next) { setError(true); return; }
if (next === initialTitle.trim()) { onCancel(); return; }
onSave(next);
```
Blur handler calls `onCancel()` directly (not `submit()`, because spec says
blur discards). Zapisz button: `onMouseDown={(e) => e.preventDefault()}` so the
input keeps focus during the click; the click handler then calls `submit()`.

Tailwind: input `bg-bgRaised rounded-field h-11 px-3 text-text w-full`,
button `h-11 px-4 bg-accent text-accentInk rounded-field`. Layout: flex row
with gap-2. Error state adds `ring-2 ring-danger` to the input.

### Refactor
Clear `error` on any value change so user gets immediate feedback that they've
recovered.
